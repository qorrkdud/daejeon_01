# 브랜드 고객 페르소나 분석

뷰티·화장품 브랜드의 **실제 리뷰 데이터**를 근거로 고객 페르소나를 만드는 스킬이다.
상상으로 만든 페르소나는 만들지 않는다. 모든 페르소나는 수집한 리뷰에서 나와야 하고, 근거 인용을 붙여야 한다.

## 기능

1. **페르소나 분석** (핵심): 리뷰 수집 → 고객 유형 분류 → 페르소나 카드 작성
2. **콘텐츠 평가** (추가): 이미 만든 페르소나의 시각으로 콘텐츠를 평가

사용자가 어떤 기능을 원하는지 분명하지 않으면 물어본다. 콘텐츠 평가를 요청했는데 그 브랜드의 페르소나가 아직 없으면 페르소나 분석부터 한다.

---

## 0단계: 브랜드 정보 불러오기

1. `brands/` 폴더에서 해당 브랜드 파일을 찾는다 (예: `brands/whipped.md`).
2. 파일이 있으면 그 설정(주력 제품, 보조 제품, 경쟁사, 수집 채널)을 따른다.
3. 파일이 없으면 사용자에게 아래 내용을 묻고, `brands/_template.md` 형식으로 새 브랜드 파일을 만든다.
   - 브랜드명 (한글·영문)
   - 주력 제품과 보조 제품
   - 비교할 경쟁 브랜드 2~3곳 (없으면 생략)
4. **업종 확인**: 이 스킬은 뷰티·화장품 브랜드 전용이다. 다른 업종이면 지원 범위가 아니라고 알리고 멈춘다.

## 1단계: 리뷰 데이터 수집 (웹)

웹 검색과 웹 페이지 읽기 도구로 리뷰와 댓글을 직접 모은다.

**수집 채널** (브랜드 파일에 지정이 없으면 이 순서로)
- 쇼핑몰 리뷰: 올리브영, 쿠팡, 네이버 스마트스토어, 브랜드 자사몰, 무신사 뷰티 등
- SNS·커뮤니티: 인스타그램, 유튜브 리뷰 영상 댓글, 블로그 후기, 파우더룸 등 뷰티 커뮤니티

**수집 비중**
- 주력 제품 리뷰 약 80%, 보조 제품 리뷰 약 20%를 목표로 한다.
- 긍정 리뷰만 모으지 않는다. 별점 1~3점 리뷰, 불만, "재구매 안 함" 리뷰를 일부러 찾아서 포함한다 (이탈 고객 페르소나에 필요).

**규칙**
- 리뷰를 지어내지 않는다. 실제로 읽은 페이지의 내용만 쓴다.
- 리뷰마다 출처(사이트명, 가능하면 URL)를 기록한다.
- 로그인이 필요하거나 접근이 막힌 사이트는 건너뛰고, 건너뛴 사이트를 결과에 적는다.
- 광고·협찬 표시가 있는 후기는 따로 표시하고, 분류할 때 비중을 낮춘다.
- 개인을 식별할 수 있는 정보(실명, 아이디, 프로필 사진 등)는 기록하지 않는다.

**리뷰는 필수다.**
- 수집한 리뷰가 **30개 미만**이면 페르소나를 만들지 않는다.
- 대신 지금까지 모은 개수와 출처를 알리고, 사용자에게 리뷰를 직접 붙여넣거나 파일(엑셀·CSV)로 줄 수 있는지 묻는다.
- 사용자가 리뷰를 직접 주면 웹 수집 결과와 합쳐서 쓴다.

## 2단계: 고객 유형 분류

미리 정한 기준 없이, 리뷰 내용에서 **자연스럽게 드러나는 패턴**으로 고객을 나눈다.

1. 리뷰마다 아래 신호를 뽑는다.
   - 피부 타입·고민 (민감성, 지성, 건성, 트러블, 각질 등)
   - 구매 동기 (성분, 사용감, 향, 가격, 비건·클린뷰티, 패키지, 추천·광고)
   - 사용 상황과 시간대 (아침·저녁 세안, 메이크업 후, 운동 후, 퇴근 후, 여행 등)
   - 생활 단서 (직업, 출퇴근, 육아, 운동, 수면 등 리뷰에 드러난 일상)
   - 선호와 비선호 (제형, 향, 패키지, 용량, 구매 채널, 즐겨 보는 콘텐츠)
   - 만족·불만 포인트
   - 재구매 의사, 이탈 이유
   - 언급된 경쟁 제품
2. 비슷한 신호가 반복되는 리뷰끼리 묶는다.
3. **충성·만족 고객 그룹 3개**와 **이탈·불만 고객 그룹 1개**를 정한다.
   - 그룹이 3개보다 적게 나오면 억지로 나누지 않고, 나온 만큼만 만들고 이유를 적는다.
4. 그룹마다 전체 리뷰 중 비중(%)을 계산한다.

## 3단계: 페르소나 카드 작성

`references/persona-card.md` 형식을 따른다.

**문체**
- 프로필 항목은 객관적인 보고서 문체로 쓴다.
- "대표 한 줄"과 콘텐츠 피드백은 그 고객이 직접 말하는 듯한 1인칭으로 쓴다.

**근거 규칙**
- 페르소나마다 실제 리뷰 인용을 3개 이상 붙인다. 인용은 짧게(한 문장 정도) 하고 출처를 표시한다.
- 리뷰에 근거가 없는 항목(예: 직업)은 "추정"이라고 표시한다.

**24시간 생활 패턴과 선호**
- 생활 패턴은 리뷰에 나온 사용 시간대와 생활 단서를 뼈대로 삼고, 빈 시간대는 같은 유형 고객의 일반적인 하루로 채우되 "(추정)"으로 표시한다.
- 시간대마다 브랜드와 만나는 순간(제품 사용, 쇼핑, SNS·콘텐츠 시청)을 표시한다. 이 순간들이 마케팅 시사점의 "언제, 어디서 말을 걸지"로 이어져야 한다.
- 선호는 좋아하는 것과 싫어하는 것을 함께 쓴다. 리뷰에서 반복된 표현을 우선한다.

## 4단계: 결과 정리

결과물 구성은 아래 순서를 따른다.

1. **분석 개요** (짧게): 수집한 리뷰 수, 채널별 개수, 수집 기간, 건너뛴 사이트, 분류 방법 2~3줄
2. **고객 유형 한눈에 보기**: 페르소나별 이름, 한 줄 요약, 비중(%) 표
3. **페르소나 카드** 3~4장
4. **경쟁 브랜드 비교** (짧게, 브랜드 파일에 경쟁사가 있을 때만): 리뷰에 나타난 "왜 이 브랜드를 골랐나 / 왜 떠났나"를 경쟁사별 2~3줄로
5. **핵심 인사이트** 3~5줄: 발견한 사실 → 마케팅에서 할 일

**출력 형식**
결과를 내기 전에 사용자에게 형식을 묻는다 (이미 말했으면 묻지 않는다).
- **마크다운**: 노션·문서에 붙여넣기 쉬운 형식
- **HTML 페르소나 카드**: 페르소나별 카드가 시각적으로 정리된 웹페이지
- 둘 다

## 콘텐츠 평가 기능

사용자가 카드뉴스, 광고 문구, 상세페이지, SNS 게시물 등을 주면 `references/content-evaluation.md` 형식으로 평가한다.

1. 평가할 콘텐츠를 확인한다 (텍스트, 이미지, URL).
2. 해당 브랜드의 페르소나를 불러온다. 이번 대화에 없으면 사용자에게 이전 결과를 달라고 하거나 새로 분석한다.
3. 페르소나마다 아래 두 가지를 쓴다.
   - **1인칭 반응**: "이 고객이라면 이렇게 반응할 것"
   - **점수표**: 주목도, 공감도, 신뢰도, 구매 의향 (각 1~5점) + 이유
4. 마지막에 종합 개선 제안을 정리한다. 페르소나 사이에서 반응이 갈리는 지점은 따로 표시한다.

---

## 하지 말 것

- 리뷰 없이 상상으로 페르소나를 만들지 않는다.
- 리뷰 내용이나 개수, 비중을 지어내거나 부풀리지 않는다.
- 리뷰를 길게 그대로 옮겨 적지 않는다. 짧게 인용하고 출처를 붙인다.
- 리뷰 작성자 개인을 특정하지 않는다.
